**dotenv-run** is a small family of packages that load environment variables from
`.env` files the same way everywhere — in the terminal, in Node.js and inside your
bundler. Configuration stays out of your codebase, exactly as the
[twelve-factor app](https://12factor.net/config) recommends.

## Why dotenv-run

<CardGrid>
	<Card title="Angular-first" icon="rocket">
		[`@ngx-env/builder`](/integrations/angular/) injects `NG_APP_*` variables into
		Angular apps with **zero config** — Webpack and esbuild builders, templates and
		`index.html` included.
	</Card>
	<Card title="Monorepo ✨" icon="setting">
		`.env` files cascade from the workspace root down to each app, so shared config
		lives in one place. Works with [Nx](https://nx.dev) and
		[Turborepo](https://turborepo.com/).
	</Card>
	<Card title="One API everywhere" icon="approve-check">
		CLI, Node.js, Vite, Webpack, Rollup and esbuild all share the same options and
		the same `.env` loading rules.
	</Card>
	<Card title="Expand & prioritize" icon="puzzle">
		Reference variables inside variables (`API_URL=$API_BASE/users`) and layer
		`.env.production` over `.env` with predictable
		[loading priorities](/getting-started/loading-priorities/).
	</Card>
	<Card title="TypeScript & ESM" icon="seti:typescript">
		Typed `process.env` and `import.meta.env`, with full ESM support.
	</Card>
	<Card title="Secure by default" icon="warning">
		Filter which variables are exposed to the client with a prefix or regular
		expression.
	</Card>
</CardGrid>
